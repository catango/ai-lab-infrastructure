# CR-43 Acceptance criteria

Verified by the implementation PRs of the plan and by settings checks that the approver runs. "Gate check" means a fixture test of a check in `scripts/checks/`, run by `./scripts/quality-gate.sh` (the `gate-tests` check) and by CI. "CI" means a green run of the named job. "Approver check" means a read-only check that the approver runs in the GitHub interface or with the operator tooling and records in the PR or the CR; Claude Code does not run it. The criteria become binding when the design PR is merged. They cover ADR-009 only; ADR-010 has its own.

| ID | Criterion | Evidence |
|---|---|---|
| S-1 | `workflow-policy` fails a fixture for each rule WP-1 to WP-14 (a `write` permission, an unpinned or comment-less `uses:`, an owner outside `allowed_action_owners`, `pull_request_target`, `workflow_run`, a secret other than `GITHUB_TOKEN`, a `paths` filter, `inputs.*` or `github.event.*` inside a `run:` value, a download piped to a shell, a checkout without `persist-credentials: false`, a job without `timeout-minutes`, a container image without a digest, a `runs-on` outside `runner_labels` or a self-hosted label, `actions/cache` and artifact actions) and passes this repository's workflows | Gate check fixtures, one failing fixture per rule and a passing one |
| S-2 | The generated `ci.yml` has the jobs `quality-gate-<arch>` (one per configured architecture) and the aggregate `quality-gate` with `if: always()`, which fails when any matrix job is not `success` and when an architecture has no runner it writes `not run: <arch>` to the summary; `pr-contract.yml` has the job `pr-contract`; no required job has a job-level `if:`, a `paths` filter, or `continue-on-error` | Template job `generate` with fixtures of the aggregate (all green, one red, one skipped); gate check `workflow-policy` |
| S-3 | Rulesets, public repository: `main-protection` requires `pr-contract` and `quality-gate` with the source GitHub Actions and is not strict; the required names equal the check names of a green run (including the expanded matrix names); a PR with a failing required check cannot be merged; creating a `v*` tag as the machine account is rejected where `release-tags` exists | Approver check: the ruleset's content and a negative test on a throwaway branch or PR, recorded in the init PR or this CR |
