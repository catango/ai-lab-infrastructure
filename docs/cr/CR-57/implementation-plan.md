# CR-57 Implementation plan

Starts only after the design PR is merged (ADR-003 section 4). Each PR runs in its own session, in `ai-lab-infrastructure` unless stated, branch `impl/CR-57-<slug>`, and declares `Implements: #57` and `Design:` with the design PR number (the last PR carries `Closes #57`, section 4). Slugs and file lists are proposals read from `main` at `85360e8`; each PR starts with an inventory that corrects them. No ADR, `design.md`, or acceptance file is edited in an implementation PR (PC-5); a needed change is a new design PR. ADR-012 is written in the design PR, not in an implementation PR.

## 1. Order and rules

The order is the approver's (review of 2026-11-23T18:27:31Z, steps 1 to 10), with **step 0** added: the `operator_paths` configuration must exist before the first removal (corrections of the independent review). The order is strict (PA-26): the repository `CLAUDE.md` keeps a rule until the PR that removes its subject (PA-11), the aggregate `quality-gate` is green after every PR, and required check names do not change. PA-26 is narrowed by the approver's round 2 decision O-3: **the approver may cut a release tag at any PR boundary whose PA-A16 run is green, except between PR 5 and PR 6.** The operator machine moves to a new tag only at or after PR 4. PA-A28 runs on a tag cut after PR 2 and is recorded in PR 3. Lab setup and the operator configuration refuse to run except at a release tag (the tag check is a pre-task of `ansible/lab.yml` and `ansible/operator.yml`). A removal PR deletes, in the same PR, the code, its tests and fixtures, the rows and links that name it in `docs/README.md` and the operations documents, and the checks that hard-code it; a link to a deleted file fails the `links` check. Each PR body gives the PC-8 section when it touches a PC-8 path and the PC-6 section when it touches a workflow (PA-A5); a path becomes a PC-8 path only once the base commit lists it, so a PR that adds profile paths states them in its body.
