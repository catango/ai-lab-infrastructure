# CR-55 Acceptance criteria

Verified by the implementation PRs of the plan. "Gate check" means a fixture test run by `./scripts/quality-gate.sh` and by CI. "CI" means a green run of the named job. "Approver check" is a read-only check the approver runs and records; Claude Code does not. The criteria bind when the design PR is merged and assume the recommended answers to Q1 to Q8 (design section 6).

| ID | Criterion | Evidence |
|---|---|---|
| XB-A1 | The manifest check accepts `targets` on a tool whose values are `amd64` or `arm64`, and rejects a third architecture name, a non-list value, and a tool with `targets` that lacks a checksum for either host architecture | Gate check fixtures (one failing fixture per case, one passing) |
| XB-A2 | `scripts/toolchain verify` runs the cross-smoke for a tool with `targets`: it compiles a fixed source, reads the ELF machine field without executing the result, passes for the target and fails closed for a wrong machine, a missing output, and a non-ELF output | Fixtures with a stub compiler; CI job `toolchain-amd64` once a tool with `targets` exists |
| XB-A3 | `scripts/cross-build <target>` refuses a target equal to the host, refuses a target not configured for this host, checks every ELF file of the output for the target machine, prints only the file count and one SHA-256, never executes a built file, and supports `--dry-run` | Fixtures with a stub build entry point |
| XB-A4 | The strict reader of `cross_builds` fails closed on any form outside its subset, on a name not in `architectures`, on `host == target`, and on any pair other than amd64 to arm64; it reads the base commit only, so a PR that adds a pair does not change the verdict on itself | Gate check fixtures; same comparison with `yq -o=json` as the PC-9 reader |
| XB-A5 | The generated `ci.yml` has the job `cross-build-<target>` on a `runner_labels` runner with only `actions/checkout`, no artifact, no cache, and no third-party Action, writes `cross-built: <target> (build only)`, and the aggregate `quality-gate` needs it and fails when it is failed, skipped, or cancelled | `workflow-policy` fixtures; template CI with the aggregate fixtures (green, one red, one cancelled, one skipped) |
| XB-A6 | Public repository: `quality-gate-arm64` runs natively on the ARM64 runner and `cross-build-arm64` runs on the amd64 runner. Private repository: `not run: arm64` in the aggregate summary, `cross-build-arm64` still runs, and PC-9 asks for the evidence line | Template CI on a public configuration; PC-9 fixtures unchanged and a new fixture for a private configuration with `cross_builds` |
| XB-A7 | `gate-evidence arm64` still refuses on an x86-64 host, and no evidence-line form is added for a cross-build | The existing PC-9 and `gate-evidence` tests pass unchanged |
| XB-A8 | The check `no-emulation` fails a fixture for qemu-user, `binfmt_misc`, a foreign `--platform`, and `dpkg --add-architecture` in a workflow, a script, and the manifest, and passes this repository and the template | Gate check fixtures; catalogue entry with class generic |
| XB-A9 | The three amendments are applied as in design section 4 with the approver's text, and `docs/README.md` states them; ADR-001 and ADR-003 are unchanged | Review of the design PR |
| XB-A10 | No script, workflow, or document of the implementation reaches, copies to, or runs on the lab VM or an operator machine; no metered runner label appears | Approver check of the PR diffs; existing `runner_labels` check |
