# CR-55 Acceptance criteria

Verified by the implementation PRs of the plan. "Gate check" means a fixture test run by `./scripts/quality-gate.sh` and by CI. "CI" means a green run of the named job. "Approver check" is a read-only check the approver runs and records; Claude Code does not. The criteria bind when the design PR is merged and assume the recommended answers to Q1 to Q4 (design section 7).

| ID | Criterion | Evidence |
|---|---|---|
| XB-A1 | `scripts/cross-build <target>` refuses a target equal to the host, refuses a name not in `architectures`, runs the project's build entry point, checks every ELF file of `build/<target>/` for the target machine field (fails on a wrong machine, a missing output, and an empty output), prints only the file count and one SHA-256, never executes a built file, and supports `--dry-run` | Gate check fixtures with a stub build entry point |
| XB-A2 | Native first: for an architecture with a runner for the repository's visibility, the matrix job runs the gate natively and runs no cross-build; for an architecture without one, the matrix job runs on a base runner, runs `scripts/cross-build`, and writes `cross-built: <arch> (build only)` and `not run: <arch>` | Template CI fixtures: public, private without arm64 runner, private with `runner_private` set |
| XB-A3 | The aggregate `quality-gate` fails when that job fails, is skipped, or is cancelled, and its summary lists every architecture not run and every cross-built one; no required job has a job-level `if:`, a `paths` filter, or `continue-on-error` | Template CI with the aggregate fixtures (green, red, cancelled, skipped, not run) |
| XB-A4 | The check `no-emulation` fails a fixture for qemu-user, `binfmt_misc`, a foreign `--platform`, and `dpkg --add-architecture` in a workflow and in a script, and passes this repository and the template; it has a catalogue entry of class generic | Gate check fixtures |
| XB-A5 | PC-9 and `gate-evidence` are unchanged: `gate-evidence arm64` refuses on an x86-64 host, a private repository without an ARM64 runner still needs the evidence line, and no evidence-line form is added | The existing PC-9 and `gate-evidence` tests pass unchanged |
| XB-A6 | No manifest field, configuration key, `builder` profile content, or toolchain engine behaviour is added, and no metered runner label appears (unless Q1 is accepted, then only through `runner_private` of one repository) | Review of the diffs; the existing `runner_labels` check |
| XB-A7 | The two amendments are applied as in design section 5 with the approver's text; ADR-001, ADR-003, and ADR-005 are unchanged (ADR-005 changes only if Q1 is accepted) | Review of the design PR |
| XB-A8 | No script, workflow, or document of the implementation reaches, copies to, or runs on the lab VM or an operator machine | Approver check of the PR diffs |
