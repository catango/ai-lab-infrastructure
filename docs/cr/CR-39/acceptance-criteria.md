# CR-39 Acceptance criteria

Verified by the implementation PRs in `ai-software-template` (see the plan). "CI" means a green run of the named template job. "Both architectures" means the workspace (x86-64) and the template's CI job on an ARM64 runner. The criteria are those of the approver's decisions of 2026-11-19 (design section 13) and become binding when the design PR is merged. T-16 is the baseline Stage 5 exit criterion. T-18 is not used (proposed and withdrawn in the discussion).

| ID | Criterion | Evidence |
|---|---|---|
| T-1 | Every tracked file has exactly one class (`owned`, `seeded`, or `template-only`) in `.template/manifest.toml`; a file without a class or with two classes fails the gate; `initialize-project` removes every template-only path. | Template job `manifest` with a passing tree and one failing fixture per case |
| T-2 | Generating from the template (export without history, then `initialize-project --config`) yields a repository with no `template-dev/`, no unfilled placeholder, a green `./scripts/quality-gate.sh --strict`, and the generated tree contains no template-only path and no CR or ADR instance from the template. | Template job `generate` on x86-64 |
| T-3 | The generated `ci.yml` runs the gate as a matrix over the configured architectures and runner labels; where no runner is available, the job summary reports `not run: <arch>` and the PR template requires a host-reported evidence line with the commit SHA; the condition reads the repository's actual private flag. T-2 also passes on ARM64 in template CI. | Template job `generate` on both architectures; fixture tests of the matrix, the `not run` summary, and the private-flag condition |
| T-4 | `CLAUDE.md` is owned and matches its manifest hash; it contains the instruction-trust rule, the Never list, and the precedence sentence, cites no platform record, and ends with exactly two imports, `docs/PLATFORM.md` then `docs/PROJECT.md`; neither imported file contains an import; no other `CLAUDE.md` and no `CLAUDE.local.md` is tracked; the files are within their size budgets. | Gate check `claude-md`, one passing and several failing fixtures |
| T-5 | `.claude/settings.json` contains every entry of `.claude/required-deny.txt` (owned core) and of `.claude/deny.platform.txt` (seeded); deleting one entry fails the gate. | Gate check `deny-list`, fixture test |
| T-6 | Each rule file has valid path scoping and is within its size budget; `public-repo.md`, `bash.md`, `workflows.md`, `docs.md`, `multi-arch.md`, and `operator.md` exist; `operator.md` states the generic operator rules (dry-run default, release tags only, prompted or short-lived credentials kept inside the script process, read-only fact collection enforced in code, output safe to paste, no infrastructure change, never run by Claude Code) and cites no platform record. | Gate check `size-budget`; rule-file test |
| T-7 | `scripts/new-cr <n> <slug>` creates the five-file CR skeleton and refuses to overwrite; `cr-layout` passes it and fails a CR with a missing file, a duplicate criterion ID, or a plan row without a criterion ID; `cr-layout` rejects an unqualified reference to another repository. `docs/adr/_template.md` has the ADR header and sections. | Gate check `cr-layout` fixtures; script test |
| T-8 | In the generated repository `pr-contract` applies PC-1 to PC-8 and TC-1 and TC-2 for design, implementation, change, template-sync, and init PRs, with the results of the template's own fixtures; PC-3 accepts qualified references only to repositories listed in `design_repos` and fails closed on an unreadable repository; PC-8 follows `operator_paths` and is inactive when that list is empty. | Fixture tests in job `skills` |
| T-9 | `template-sync` from version A to B overwrites owned files (including locally changed ones without an override entry), adds and removes owned files, never changes a seeded file, honours and lists the entries in `.template/overrides.toml` and records them as `override` in `.template/state.toml`, overwrites and lists drift limited to `uses:` lines, and updates `.template/state.toml`; a second run changes nothing. | Template job `sync` |
| T-10 | `template-sync` rejects a target that is not a tag, a tag whose commit is not contained in the template's default branch, a downgrade, and a tag whose commit differs from the one recorded; the repository's own copy of the script performs every check and the copy; the template clone runs with credential helpers disabled; no workflow, in the template or the payload, runs it. | Template job `sync`; negative fixtures; workflow scan in the gate |
| T-11 | `review-threads` outputs only review threads, review comments, and review summaries authored by the approver, matched by the immutable account ID from the configuration and not edited by any other account; a look-alike login, a bot, the machine account, and an approver comment edited by another account are excluded and only counted; it refuses PRs not authored by the machine account and PRs from forks; it contains no call that resolves a thread, submits a review, or merges. | Fixture test with approver, machine-account, bot, look-alike, and edited-by-other authors; static check of the script's calls |
| T-12 | `pr-checkpoint` reads and edits only the text between the checkpoint markers, updates the PR body with the REST PATCH call, and marks ready with the GraphQL mutation; none of its calls is `gh pr edit` or `gh pr ready`. | Fixture test; static check. The same calls run on the workspace in the implementation PR. The check on the lab VM is deferred to Stage 6 and recorded as open until then |
| T-13 | Each Skill in design section 6 exists as `SKILL.md` within its size budget, names a script that exists, and every script has `--fixture` or `--offline` and a test; `initialize-project` creates no label, ruleset, repository, collaborator, or setting (it prints proposals); `start-cr` and `cr-context` refuse an issue not authored by the approver or the machine account; `start-cr` creates no label and labels only after the user confirms the class in the session; `sync-template` never writes `.template/overrides.toml`. | Gate check `size-budget`; job `skills`; static check of `initialize-project` and `start-cr` |
| T-14 | The template's CI installs the gate tools with the template's own engine and CI manifest, and fetches no other repository; every download in the CI manifest has amd64 and arm64 artifacts with checksums; CI runs the gate with all generic and template checks and the template jobs `manifest`, `generate`, `sync`, `skills`, and `leak`; every workflow passes the workflow-policy and no-Claude-in-workflows checks; the design section 11 assumptions are the ones implemented, and any deviation is reported. | A green template CI run on a test PR; the section 11 table checked in the final implementation PR |
| T-15 | A scan of the template and of a generated tree finds no identifier pattern (tenancy or resource OCIDs, IP addresses, emails, keys, fingerprints, tokens); `public-repo-hygiene` runs for a private repository too; a seeded identifier makes it fail. | Template job `leak`; fixture test |
| T-16 | **Stage 5 exit (baseline section 6).** (a) The scripted dry run passes in template CI on both architectures with two different configurations; (b) the approver's real run in a throwaway public repository with this platform's preset completes five steps: generation, an init PR that passes `pr-contract`, a change PR that fails and then passes, one review round in which only the approver's comment is acted on, and one template-sync PR from a second tag. Links to its PRs are recorded in the last implementation PR, and afterwards the repository and the collaborator are removed. | The dry-run report in the last implementation PR; the approver's links and note; the removal confirmed by the approver |
| T-17 | Gate check `owned-drift` fails a PR that changes an owned file without a matching entry in `.template/overrides.toml`, and passes with one. | Gate check fixtures |
| T-19 | Gate check `forbidden-api` fails a script fixture for each forbidden REST call and each forbidden GraphQL mutation (merge, review submission, auto-merge, rulesets, collaborators, repository settings). | Gate check fixtures, one per call |
| T-20 | An init PR passes once, fails when `.template/state.toml` exists on the base branch, and fails on any path outside TC-2; `initialize-project` prints the configured post-init actions and creates no label, ruleset, repository, or setting. | Fixture tests of TC-2; static check of `initialize-project` |
| T-21 | A scan of the payload and of a generated tree finds no reference to `ai-lab-infrastructure`, its ADR or CR numbers, OCI, platform host names, or a fixed architecture; the generated CI passes with network access limited to the template and its own repository; the dry run passes with a neutral configuration and a second, different one. | Template job `leak`; job `generate` with two configurations |
| T-22 | Gate check `operator-contract` fails one fixture per forbidden pattern (`shell=True`, `os.system`, `eval`, `exec`, a token read from `argv` or the environment, a subprocess outside the configured allowlist, a missing dry-run default) when `operator_paths` is set, and is inactive when it is empty; `operator_guard` refuses an apply run from an untagged commit or from a tag not contained in the default branch. | Gate check fixtures; guard test |

Entry to Stage 5 also needs ADR-009 and ADR-010 approved. This CR delivers ADR-008 only, and none of these criteria covers the other two.
